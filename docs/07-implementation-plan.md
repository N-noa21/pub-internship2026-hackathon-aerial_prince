# 07. 実装の進め方

> 一覧に戻る: [README.md](README.md) ／ 前: [06-snowflake.md](06-snowflake.md) ／ 次: [08-open-questions.md](08-open-questions.md)

**方針: Streamlit で一周遊べることを確認し（`app/`）、本命は Next.js（`web/`）で作り込む。**
ゲームループ（[01-concept.md](01-concept.md)）が最後まで通っていない状態で演出を作り込むと、何が面白いのか判断できなくなる。

## 技術選定のまとめ

| 項目 | 決定 | 補足 |
| --- | --- | --- |
| アプリ | **Snowflake App Runtime（Next.js / TypeScript）** | デザインの自由度で選択。`web/` |
| 言語 | TypeScript | React / Next.js |
| AI ライブラリ | **Vercel AI SDK（TypeScript）** | `ai` + `@ai-sdk/gateway` + zod。動作確認済み |
| 推論先 | **Cortex の OpenAI 互換エンドポイント**を第一候補 | 外部通信なしで閉じられる可能性がある |
| 商品データ | **楽天 API で事前にカタログ化 → エージェントが判定** | 実行時の外部通信なし。[05-data.md](05-data.md) |
| 打ち首アニメ | CSS のみの断片を AI に量産させる | [03-presentation.md](03-presentation.md#アニメーション量産の仕組みai-に作らせる) |

詳細と出典は [06-snowflake.md](06-snowflake.md)。

## フェーズ 1: とにかく一周遊べるものを作る

**ゴール: わがままを入力 → 5 人が順に献上 → 斬る／選ぶ → 何か結果が出る、が動く。**

- [ ] Streamlit in Snowflake でアプリの雛形をデプロイする（`snow` CLI で `CREATE STREAMLIT` まで通す）
- [ ] **AI SDK for Python が Streamlit in Snowflake で動くかを最初に確かめる**
      （Python バージョン・パッケージ導入・Cortex の OpenAI 互換エンドポイントに向けられるか）
      → ここが詰まると設計が変わるので、**着手初日に潰す**
- [ ] **楽天ウェブサービスに「バックエンドサービス」として登録し、実行元 IP を登録する**
- [ ] 取り込みバッチを書き、少量（キーワード 20 語ぶん程度）でカタログテーブルを作る
- [ ] タイトル画面（ロゴ＋ START ボタン）
- [ ] わがまま入力 → LLM が家臣 5 人分の献上品を**構造化出力で 1 回にまとめて生成**（5 人目は「まとも枠」）
- [ ] 献上品カードを 1 枚ずつ表示し、「採用」「打ち首」の 2 ボタンで進む
- [ ] 5 人斬るか、1 人選ぶかで終了 → 結果テキストを出す

この時点では、**見た目は Streamlit の素のままでよい。** 打ち首は画面から消えるだけでよい。
ここまで通して初めて「面白いかどうか」が判断できる。

## フェーズ 2: 面白くする

**ゴール: 人に見せて笑いが取れる状態。**

- [ ] 家臣 5 人のキャラ付け（口調・立ち絵）と、属性ごとの献上品の引き分け
- [ ] **ズラし方の型**をプロンプトに落とし込み、提案の面白さを安定させる（[02-mechanics.md](02-mechanics.md#ズラし方の型プロンプト設計の中心)）
- [ ] 収集キーワードを設計し、カタログを本番規模まで広げる（フィルタも同時に）
- [ ] カタログに無い語が来たときのフォールバック
- [ ] **打ち首アニメーションの型を決め、AI に量産させる**＋プレビューギャラリーを作る
- [ ] 判決理由（任意入力）を追加し、エンディング生成に渡す
- [ ] 診断レポート＋後日談（[04-ending.md](04-ending.md)）
- [ ] ロイヤル感のある UI に着せ替える（[03-presentation.md](03-presentation.md#ui-デザインの方向性)）

## フェーズ 3: 欲張り枠

**ゴール: デモで「おっ」と言わせる。落ちても本編が壊れないものだけをここに置く。**

- [ ] カメラ撮影 → 王子アバター（まずは CSS 合成、可能なら画像生成）
- [ ] エンディングでのアバター再利用・シェア画像
- [ ] 打ち首演出の実行時生成（フォールバック必須）
- [ ] プレイログの集計（打ち首率ランキング・人気の献上品）
- [ ] 効果音・BGM

## 進め方の原則

- **フェーズ 1 を最短で終わらせる。** 面白さの判断が全部そこから始まる。
- フェーズ 3 の項目は**単体で落ちても本編が動く**ように作る。落ちたら黙って非表示にする。
- 外部通信が必要な機能（画像生成・EC API 直叩き）は、**使えないと判明した場合の代替を先に決めてから**着手する。
