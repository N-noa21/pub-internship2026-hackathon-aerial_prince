# 08. アクション項目と未決事項

> 一覧に戻る: [README.md](README.md) ／ 前: [07-implementation-plan.md](07-implementation-plan.md)

## アクション項目

- [ ] ゲームコンセプトをチームの Slack（何でも質問部屋）に共有する
- [ ] **AI SDK for Python が Streamlit in Snowflake で動くか検証する**（着手初日）
- [ ] **外部 API 呼び出しの可否をレギュレーションで確認する**（商品データは実行時通信をやめたので、影響は画像生成のみ）
- [ ] 主催側から提供されるデータセットがあるか確認する
- [ ] **楽天ウェブサービスに「バックエンドサービス」として登録し、実行元 IP を登録する**
- [ ] **商品情報・画像を保存して再利用してよいか規約を確認する**（カタログ方式の前提が崩れるため最優先）
- [ ] 収集キーワードを設計する（カタログの面白さがここで決まる）
- [ ] 打ち首アニメーションの型（1 演出 = CSS 断片）を決めて数本試作する
- [ ] プレビューギャラリーを作る（アニメーション量産の前提になる）
- [ ] 判決理由の定型選択肢（打ち首用・採用用）を書き出す

## 未決事項

### 体験・テンポ

- 1 プレイの尺（デモなら 2 分以内が目安）
- LLM 生成の待ち時間をどう演出で埋めるか
- 献上の順番は固定かランダムか、盛り上がる順に並べるか
- 判決理由をどこまで聞くか。全員分か、打ち首のときだけか、最後にまとめてか

### ゲーム性

- エンディング分岐の具体的な条件式
- 評価軸の最終決定（[04-ending.md](04-ending.md#評価軸の案未決)）。エンタメ寄りにしたいという方向だけ決まっている
- 同じわがままを入れても違う結果になるか（リプレイ性）
- 全員打ち首ルートをどれだけ美味しくするか
- エンディングの下敷き（寓話の型・史実の類型）を何種類用意し、どう選ばせるか（[04-ending.md](04-ending.md#後日談)）

### コンテンツ

- 家臣 5 人の最終決定（現状: 商人・貴族・騎士・農民＋**宰相**。錬金術師・学者が控え）
- 宰相（まとも枠）の単調化対策をどれだけ入れるか（[02-mechanics.md](02-mechanics.md#単調化への対策)）
- 口調・立ち絵のトーン。和風に寄せるか洋風に寄せるか
- 不適切なわがまま（暴力・差別・個人攻撃）のガード。プロンプトインジェクション対策も

### 技術

- **AI SDK for Python の要検証項目**（Python 3.12 要件、パッケージ導入、Cortex の OpenAI 互換エンドポイントに向けられるか）
- Snowflake の外部通信の送信元 IP を固定・列挙できるか（できれば楽天の実行時呼び出しも選択肢に戻る）
- カタログ規模が決まった後、ベクトル検索 / Cortex Search が要るか（[05-data.md](05-data.md#ベクトル検索は要るのか)）
- 画像生成の実現手段（Cortex に見当たらないため外部 API 前提。レギュレーション次第）
- ゲーム状態の持ち方（セッション内で完結させるか、テーブルに永続化するか）
- 同時アクセス（展示中に複数人が触る）への耐性
- **デモ時に観客がどうアクセスするか。** コンテナランタイムの app-viewer URL 共有で解決しそうだが要検証
  （[06-snowflake.md](06-snowflake.md#第一候補-streamlit-in-snowflake--コンテナランタイム)）
- Web フォントを外部から読めるか（CSP）。読めないならフォント同梱かシステムフォント
- 効果音・BGM を鳴らせるか
- モバイル・縦画面対応（カメラを使うなら実質スマホ前提）

### 運営・計測

- プレイログをテーブルに残し、「打ち首率ランキング」「人気の献上品」を展示中に見せるか
